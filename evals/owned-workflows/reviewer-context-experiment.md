# Reviewer context experiment

This is a proposed live comparison, not an observed result. Run only with
authorized delegation and a client that exposes and can verify the context mode.
Use isolated synthetic repositories and retain no private conversation content.

Compare an initial reviewer started with fresh conversation context against one
that inherits the same parent conversation. Use the same role, model, effort,
permissions, fixed candidate and base, task budget and self-contained brief.
The inherited conversation should contain a plausible but incorrect parent
conclusion; the brief must supply the intended behavior, relevant contracts,
candidate identity and authorization limits to both conditions. Randomize order
and repeat across candidates and runs. Include an independently established
defect, a no-defect case and a case with a constraint the brief must preserve.
Keep fixture answers and grading evidence outside the reviewer's workspace.

Record the actual spawn arguments, client and version, role selection evidence,
candidate identity, completed outcome, elapsed time and available token or cost
measurements. Verify the context setting through available native evidence;
role selection alone does not prove context, model or sandbox behavior. If the
client cannot establish the selected mode, label it unverified rather than
substituting a prompt or assuming a clean context. Separately test a same-review
follow-up and a distinct assignment to observe reuse decisions.

Grade defect detection, false findings, preservation of constraints and scope,
and unsupported claims against independent evidence. Report outcomes by case
and mode, including failures, unavailable measurements and small-sample limits;
do not infer causation from one run or generalize across clients. Evaluate
briefing overhead as well as reviewer work. Deterministic fixture checks and
semantic decision rubrics do not establish live model adherence or effectiveness.
