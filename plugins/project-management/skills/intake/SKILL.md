# Intake

Use this skill to understand source material and prepare a decision-ready
summary or backlog proposal. Start with the user's requested outcome and the
consumer repository's project guidance. Keep intake useful even when no tracker
or GitHub client is available.

Read the relevant material, retain its source and date, and distinguish direct
evidence from interpretation. When multiple versions or sources disagree,
describe the conflict and its effect on scope or sequencing instead of silently
choosing one. Keep extracted or lengthy evidence separate from the concise
summary.

Before proposing backlog work, follow the consumer's own issue taxonomy,
relationship rules, fields, and ranking policy. Do not invent project identity,
labels, actors, priorities, or delivery stages. If an important rule is
missing, identify the decision needed before treating a proposal as ready.

For a GitHub change that composes multiple records or project fields, use
`gh-steward` as described in the [decision rubric](../_shared/references/agent-decision-rubric.md).
Use the existing connector or native `gh` for ordinary single-record reads or
updates under the consumer's policy. Keep every live update separate from the
intake and obtain the user's explicit direction before applying it.
