# Understanding formats

Read this reference when the reader must understand relationships, changing
assumptions, a complex process or a consequential comparison. Preserve the
requested deliverable and use a compact answer for routine facts and simple
actions. An elaborate artifact has a cost in reading, maintenance and validation;
choose it only when it makes the reader's task easier.

## Choose for the reader's decision

Identify what the reader needs to explain, compare, decide or do. Choose the
representation that makes that work inspectable:

| Representation | Useful when | What to preserve |
| --- | --- | --- |
| Prose | A direct answer, causal explanation or ordered instruction is enough. | Main point, conditions, evidence and a concrete example where needed. |
| Table | The reader must compare options using the same dimensions. | Comparable criteria, unknown entries and the source of values. |
| Diagram | Relationships, ownership, dependencies or state transitions carry the meaning. | Named entities, direction, legend and important exceptional paths. |
| Interactive artifact | The reader needs to vary assumptions or compare scenarios. | Visible inputs, units, sources, model limits and a default view that communicates the main result. |
| Video | Motion, temporal behavior or narrated visual explanation contributes useful understanding. | Inspectable script, captions or equivalent text, evidence links and any unresolved claims. |

These are choices, not a progression toward a more impressive format. A diagram
can omit nuance that prose needs to retain; an interactive scenario can imply
precision the inputs do not support. Pair formats only when each contributes
something the reader needs.

## Preserve inspectable reasoning

Make known facts, inference, proposals and uncertainty distinguishable in the
artifact itself. Show sources near the claim or through usable links. For an
interactive model, retain supplied inputs separately from adjustable assumptions
and derived outputs. State units and calculation relationships; do not present a
hypothetical result as an observed outcome. Keep unsupported values unknown.
Derive decision points from the supplied workflow and existing authority. A stage
in a diagram is not automatically a human approval gate. Show routine authorized
checks as actions, and distinguish new decisions from permissions already granted.

The reader should be able to trace a consequential conclusion back to evidence
without watching a video again or reverse-engineering a visualization. Keep a
concise text explanation or source table where the visual alone cannot preserve
that trace. A polished rendering does not validate the facts or model.

## Use capabilities available in the task

Inspect available tools and applicable artifact skills before promising a format.
Use the relevant diagram, visualization, document, presentation or video tools
when they exist. For an interactive HTML artifact, use the existing consumer
stack or available artifact workflow rather than inventing a new dependency for
a simple explanation. Reuse a small static diagram when interaction adds little.

If the requested output cannot be rendered or exported with available tools,
state the actual limit and provide a useful supported representation. A script
or storyboard is preparation for a video; call it that. Tool availability does
not establish provider authentication, permission, export quality or successful
rendering. Sending, uploading and publishing follow the user's authorized stage.

## Check understanding and artifact behavior

Inspect the completed artifact in its actual format when tools permit. Verify
labels, links, calculations, interaction states and meaningful uncertainty
against the source. Check the reading order and provide text access to essential
visual meaning. Report a rendering or interaction check as unverified if it was
not exercised.

Use a qualitative acceptance check appropriate to the reader's task: can they
identify the decision, explain the main relationship, see what is uncertain and
locate the supporting evidence? For a procedure, can they identify the next
action and its success condition? For scenarios, can they tell which inputs
changed and why the conclusion changed?

These questions guide review; they are not measured human comprehension unless
someone actually assessed the artifact. Do not invent a readability score,
comprehension percentage or time saving. When reader feedback is available,
record the observed confusion and repair the representation that caused it.
