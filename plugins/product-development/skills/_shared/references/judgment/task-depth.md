# Choose a stronger approach to the same engineering outcome

Use for an explicit request for greater depth, or when summarized evidence or
an unexamined method could materially change a consequential engineering choice.
A routine understood edit can proceed directly. Preserve the user's outcome,
accepted behavior, delivery stage and resource limits.

Identify a professional practice that would change the approach, then connect:

- **Source:** Inspect the closest useful authorized evidence: accepted contracts,
  exact source, build records, traces or reproducible inputs. Retain revision,
  observation limits and transformations. More granular material is useful only
  if it answers the question; do not collect everything or override accepted
  policy with observed implementation behavior.
- **Method:** Choose a concrete technique and explain why it distinguishes the
  relevant alternatives. Reproduction, work accounting or a small profile may
  answer more than a speculative rewrite. Borrow a technique from another field
  only when it resolves a real uncertainty within available tools and budget.
- **Check:** Identify an observable result that could reject the approach. Use
  the existing behavior tests, performance comparison or product verification
  procedure, with expectations grounded independently of the candidate. Another
  agent's agreement or a test that repeats the implementation is insufficient
  by itself. Preserve unknown acceptance thresholds as unknown.

For example, a shorter build duration is weak evidence if the candidate completes
less work or has more failures. Inspect job records and workload identity before
changing the workflow; compare equivalent successful work and retain correctness
checks. If traces are unavailable, make a bounded recommendation or use existing
records, naming what remains unresolved instead of claiming a measured cause.

Explain a materially changed source, method or check naturally. Do not require
four headings, an expert persona, a prompt rewrite or a principle footer. If the
existing approach already fits, keep it. For a prompt-rewriting request, return
the improved prompt without executing it. For already-authorized execution,
continue through the selected existing procedure and requested endpoint; this
reference adds no confirmation round. A broader outcome remains a proposal.

Treat stretch targets as hypotheses to test against real constraints, not new
requirements. Do not invent expertise, tools, data, pass criteria or results,
install tools, launch additional agents or expand access merely to deepen a task.
