# Steer engineering work with a short principle name

Use when the user names a principle or a consequential choice benefits from
this vocabulary. Read only the applicable linked guidance. These names route
to existing procedures; they are not additional discoverable skills or a
checklist to run on every task.

| Name | Trigger and owning guidance |
| --- | --- |
| Attack the Premise | Repeated failed fixes share an assumption: [reset the premise](judgment/premise-reset.md). |
| Check Transient Bounds | An average or full-cycle result may conceal a peak: [benchmarking](benchmarking.md). |
| Separate Before Coordinating | Concurrent actors might not need one mutable target: [shared-state design](judgment/shared-state.md). |
| Build the Lever | Repetition or replayable evidence earns automation: [repeatable work](judgment/repeatable-work.md). |
| Minimize Reader Load | An abstraction may relocate caller burden: [design judgment](judgment/modernization-and-design.md). |
| Prove It Works | A proxy leaves the requested outcome unknown: [verify-product](../../verify-product/SKILL.md). |
| Encode Lessons in Structure | A demonstrated recurring mistake warrants a durable guard: [recurrence prevention](recurrence-prevention.md). |

When a principle materially changes a choice, explain the choice and evidence
in the normal task response. Name the principle when the user used that name or
when it makes the explanation clearer. For example, a premise reset can change
the next step from another allocator rewrite to measuring work assignment.
Do not invent a changed decision, list unused names, claim body use from a
name-drop, or require a closing principles section. A routine edit can proceed
without this index. Consumer constraints and live authority still govern.

The [adaptation record](judgment/sources.md) separates source inspiration from
claims of effectiveness; evaluate outcomes independently of principle mentions.
