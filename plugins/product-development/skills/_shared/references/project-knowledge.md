# Consumer project knowledge

Use an existing consumer convention: selected solution notes, architecture
records, incident summaries or another documented store. Search by symptom,
component and domain vocabulary, then open plausible matches. A matching title
is insufficient; inspect context, revision, constraints and verification. Avoid
loading the entire store or unrelated history. No store means no automatic
bootstrap, new database or AGENTS.md edit.

Retrieve selectively before repeated diagnosis or a consequential design choice.
Treat prior evidence as a lead: verify drift-prone claims against current source
or authorized runtime observation. Historical receipts can explain a past state
without proving the present environment. Never silently replay an ambiguous
operation described in a record.

For capture, retain only non-obvious verified reasoning whose loss would cause
recurrence or substantial rediscovery. Final code and tests already explain most
routine changes. Search for overlap first; enrich a canonical record rather
than copying it. Use the consumer format, preserving useful source attribution.

A meaningful record includes symptom and context; cause or decision; rejected
alternatives and their evidence; remedy and applicability limits; exact source
revision and artifacts; affected components/search terms; last verification
and status. Separate confirmed, historical and unverified claims. Do not promote
a narrow fix into a universal policy or copy credentials and raw transcripts.

For refresh, age alone is not wrongness. Keep accurate knowledge without churn.
Fix supported descriptive drift, retain operational unknowns and check inbound
links before restructuring. Preserve independent accepted policy when current
implementation contradicts it; report a possible product regression. Missing
source or a changed filename does not prove the problem domain disappeared.
Supersession must preserve unique reasoning, context and a trustworthy successor.
Deletion remains bounded by task authorization and supported evidence.

Project knowledge does not authorize global memory updates, which require an
explicit user request. Root instructions, configuration, product code, provider
operations and external messages are separate scopes, not capture side effects.
