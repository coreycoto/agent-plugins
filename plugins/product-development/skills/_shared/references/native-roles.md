# Native engineering roles

Use roles only when delegation is authorized, available and useful. Inspect the
current spawn selector before claiming usability. Installation does not reload
an active chat or establish provider access. The parent can execute every owned
procedure without subagents; do not create specialist roles for review lenses.

| Role | Assigned task and boundary |
| --- | --- |
| `pd_explorer` | Focused source question; read-only work |
| `pd_diagnostician` | Reproducer, competing explanations and probes; temporary evidence, no product edits |
| `pd_architecture_adviser` | Explicit difficult architecture escalation; read-only advice |
| `pd_implementer` | Accepted intent, owned local files, focused validation |
| `pd_transformer` | Explicit mechanical rule, owned files, deterministic completion |
| `pd_reviewer` | Exact candidate, correctness and meaningful missing evidence; read-only work |

Assign objective, input evidence, owned files or read-only scope, success
condition and requested delivery stage. Tell writers that others share the
checkout; preserve concurrent edits and return unresolved product, architecture,
privacy, security or authorization decisions. Do not change candidate state
while another task's validation reads it.

Collect results and material limits before relying on them. A launch receipt is
not a completed review or implementation. Native selection receipts establish
role selection, not loaded model or enforced permissions. Sandbox defaults do
not override the parent's live authorization. Installation and native hook
consent remain in `manage-codex-agents`; a missing role never licenses silently
installing or changing trust settings.
